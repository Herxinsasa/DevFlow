# Code Committer - 提交辅助

## 触发

仅用户明确要求提交、commit、发布、changelog 或 push 时触发。

## 提交门禁

1. 计划存在时，目标任务完成且活动阻塞已说明；T0 无计划不因此阻塞。
2. `.claude/.review-status.json` 结论通过，范围覆盖所有暂存代码，文件哈希/diff 指纹仍匹配。
3. 必要验证已通过；等待用户验收、失败或无法执行且未获风险接受时停止。
4. 构建凭据与当前代码指纹匹配；没有有效凭据时调用 hook 构建检查。
5. 暂存范围不包含用户无关修改、运行状态、日志、缓存或构建产物。

代码变化使审查和构建凭据失效；纯文档变化不使构建凭据失效。纯文档和纯资源变化可跳过构建；仅注释变化须有验证阶段的人工豁免记录，否则仍按源码变化处理。所有情况仍需核对审查范围。

提交时代码审查凭据缺失或失效，先执行 `code-review`；构建凭据缺失或失效，再执行正式构建。用户在自测期间选择暂不审查或编译只表示延后，不能作为代码提交豁免。

## 构建复用

测试阶段或提交前检查可写 `.claude/.build-status.json`：命令、目标、结果、指纹模式、代码指纹和时间。提交前凭据按暂存区计算；存在未暂存代码变化时停止构建，避免构建内容与提交内容不一致。`pre-commit-check.ps1` 匹配有效凭据时不重复构建，否则执行一次项目构建并更新凭据。

## 提交内容

先展示实际变更清单、简洁 changelog 和 commit message。提交信息按实际变更写“新增/修改/修复/验证”，每条简短，不复述文档过程。用户确认后才执行 `git add` 和 `git commit`；只有明确要求才 push。

## 输出

- 实际提交范围和排除项。
- 审查、验证与构建凭据结论。
- changelog、commit message 和用户要求的 Git 操作结果。
