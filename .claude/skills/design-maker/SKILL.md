# Design Maker - UI 方案与原型

## 定位

回答 UI “看起来和操作起来怎样”。需求规格负责显示/隐藏、格式、业务结果等业务事实；`design-writer` 负责控件、类、信号、状态、数据映射等技术实现。本 Skill 不替代二者。

## 触发条件

仅满足任一条件时调用：

- 新页面或现有页面有多种合理布局。
- 复杂交互、状态切换或信息层级需要方案确认。
- 用户提供截图、Figma、Pencil、HTML 等稿件，需要解析或补齐。
- 实现前必须让用户选择视觉或交互方案。

简单字段、文案、显示规则、复用已有页面模式通常跳过。调用本 Skill 不提升需求等级。

## 输入优先级

1. 已确认需求规格中的 UI 业务事实。
2. 用户提供的界面稿与本次确认。
3. 项目现有 UI、组件规范和同类页面。
4. 已闭合影响面中的页面入口和约束。

不强制要求 `design-brief.md`，不强制建立设计系统。输入冲突时提示用户，不自行取舍。

## 工作步骤

1. 读取输入和现有同类页面，识别真正的设计歧义。
2. 只向用户确认会影响布局、视觉层级或交互路径的选择。
3. 形成页面结构、区域布局、字段呈现、交互和必要状态方案。
4. 仅在静态文档无法消除歧义时制作原型；工具按现有能力和用户指定选择，不强制 Figma/Pencil。
5. 输出后提示用户查阅并标记“需要确认”。

## 输出

主文档：`docs/05-UI/<迭代ID>-UI设计.md`。

```markdown
# <迭代ID> <主题>UI设计

> 状态：草稿 / 待确认 / 已确认
> 需求规格：<路径>
> 参考界面：<路径、截图或 —>

## 页面与布局
<只描述本次变化>

## 交互与状态
| 场景 | 用户操作 | 界面反馈 |
|---|---|---|

## 视觉约束
<复用项目规范；仅列本次特殊约束>

## 原型
<源文件、预览或截图；未制作则省略>

## 当前阻塞问题
<仅活动问题；无则省略>
```

原型存放在 `docs/05-UI/prototypes/<迭代ID>/` 或项目既有 UI 设计目录。不要记录工具选择过程、无关设计系统或 changelog 流水。

## 边界

- 不更改已确认 UI 业务规则。
- 不决定 Qt `.ui`、类拆分、信号槽、状态管理和接口映射。
- 不为模板完整而补全加载、空、错误状态；仅覆盖需求实际涉及的状态。
