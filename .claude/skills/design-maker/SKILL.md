# Design Maker - UI 原型

## 职责

回答“界面长什么样、怎么操作”。产出可视化交付物，例如 Figma、Pencil、HTML/CSS 原型、Canvas/PNG/SVG 设计稿，并把用户确认的关键界面事实留给详细设计和验收使用。

需求规格负责显示/隐藏、字段含义、业务规则和验收事实；`design-writer` 负责组件或对象边界、事件、状态、数据映射和生命周期等技术实现。本 Skill 不写完整 UI 设计报告，不替代详细设计。

## 触发条件

仅满足任一条件时调用：

- 用户明确要求“画原型”“出设计稿”“做界面效果”“生成 Figma/Pencil/HTML 原型”。
- 新页面或现有页面存在多种合理布局，需要用户直观看到后确认。
- 复杂交互、状态切换或信息层级仅靠文字难以确认。
- 用户提供截图、Figma、Pencil、HTML、手绘稿等，需要解析、补齐或转成原型。

简单字段、文案、显示规则、复用已有页面模式通常跳过。调用本 Skill 不提升需求等级。

## 输入

按优先级读取：

1. 用户当前确认和界面稿。
2. 已确认需求规格中的 UI 业务事实。
3. 已闭合影响面中的页面入口和约束。
4. 项目现有同类页面、截图、组件风格和交互习惯。

输入冲突时提示用户，不自行取舍。缺少配色、间距或组件细节时，优先复用项目现有风格；无法判断时先用低保真原型表达结构。

## 交付物选择

用户指定交付方式时优先遵循；未指定时根据可用工具、项目现有资产和后续查阅/修改成本选择合适形式，不把某一种工具写成固定默认。

| 类型 | 适用场景 | 输出 |
|---|---|---|
| Figma | 需要交付给设计师或团队已有 Figma 流程 | Figma 链接、关键页面截图 |
| Pencil | 需要开源原型源文件或项目已有 Pencil 流程 | `.pen` 源文件、截图 |
| HTML/CSS 原型 | 需要可预览、可点击、易修改，且当前环境适合本地交付 | HTML/CSS/JS 文件、本地预览 |
| Canvas/PNG/SVG | 只需要静态视觉效果 | 图片或 SVG |

选择依赖外部连接的工具时先检查可用性；不可用时告知用户配置缺失，并改用当前可用、能够表达同等界面事实的交付形式。

## 工作流程

1. 读取输入和同类界面，判断需要原型解决的问题。
2. 确认交付物类型；用户未指定时根据可用能力和项目事实选择。
3. 生成原型或设计稿，覆盖本次实际涉及的页面、区域、交互和必要状态。
4. 记录原型表达的关键界面事实：入口、字段、默认值、显示/隐藏、启用/禁用、关键交互、反馈结果和覆盖状态。业务规则仍以需求规格为准。
5. 对 HTML/CSS 原型启动本地预览；对图片或工具文件提供源文件和截图位置。
6. 将产物标记为“待确认”，提供入口、覆盖范围、关键差异和待确认项，将流程置为 `waiting_confirmation` 后停止。用户确认后把差异和最终选择写回索引，再进入详细设计或计划。

原型应尽量覆盖本次需求涉及的正常态、加载态、空态、错误态和关键交互；未涉及的状态不为模板完整而补齐。

## 输出

原型文件放在：

```text
docs/05-UI/原型/<迭代ID>/
```

可按需生成简短索引：

```markdown
# <迭代ID> <主题>UI原型

> 状态：草稿 / 待确认 / 已确认
> 需求规格：<路径>
> 原型入口：<路径或链接>

## 原型范围

| 页面/模块 | 交付物 | 覆盖状态 |
|---|---|---|

## 已确认界面事实

| 页面/区域 | 入口与字段 | 状态与交互 | 确认结论 |
|---|---|---|---|

## 当前阻塞问题

仅活动问题；无则省略。
```

不要记录工具选择过程、设计系统说明、changelog 流水、类拆分、接口映射、信号槽或状态管理实现。

## 边界

- 不更改已确认 UI 业务规则。
- 不决定组件或对象拆分、事件机制、状态管理和接口映射。
- 不生成完整 UI 设计报告。
- 不因“涉及 UI”机械触发；只有需要原型确认时才触发。

## 完成前自检

在输出原型、设计稿或索引并提示用户确认前执行。未通过项先修正；仍有界面歧义时保持待确认，不进入详细设计或计划。

- 是否真的需要原型来消除歧义，或用户已明确要求？
- 交付形式是否符合用户指定、可用工具和项目现有资产，而非机械固定某一种工具？
- 是否优先复用用户稿和项目现有界面风格？
- 是否产出了可查看的原型入口、源文件或截图？
- 是否记录了会约束详细设计和验收的入口、字段、状态、交互与确认结论？
- 是否没有写完整 UI 设计报告和技术实现设计？
