# Dev Builder - 编码调度

## 执行策略

| 场景 | 执行者 |
|---|---|
| T0、简单 T1 | 主 Agent 可直接编码 |
| T1 多个独立边界或适合并行 | 按需使用 implementer |
| T2/T3 | 默认独立 implementer |

同模块、共享行为和连续任务可复用一个 implementer；机械重复接入整体派发一次，不按任务行强制新建。implementer 不可用时，T0/T1 可由主 Agent继续；T2/T3 通知用户，确认降级后由主 Agent实施并加强独立审查。

## 输入

- 当前任务及关联 `REQ-xxx`。
- T2/T3 的详细设计相关章节；T0/T1 的简要影响和最小实现约束。
- 按需 UI 设计。
- 项目约束、同目录代表性代码和允许范围。

只提供当前行为需要的上下文，不重新收集整套文档。

## 执行步骤

1. 核对基线和工作区。HEAD 变化只有影响目标代码事实或契约时才暂停重查；保留用户原有修改。
2. 选择依赖已满足的任务，写入“执行中”，同步 `progress.json`。
3. 从项目文档和相邻代码提取编码、行尾、命名、注释、日志与框架约定。
4. 选择执行者并实现。缺少需求、接口、数据或 UI 契约时返回对应前置阶段，不自行设计。
5. 执行最快的局部检查或类型检查；正式构建和完整测试留给 `code-tester`。
6. 核对需求、范围和最小实现约束，更新任务为已完成或阻塞。

开发计划只更新当前状态和必要阻塞，不追加执行时间、Agent 名称、Agent ID 或过程日志。

## Qt 与注释

- Qt Widgets 已有 `.ui` 且控件静态固定时，在 `.ui` 中创建并通过 `ui->控件` 使用；动态创建必须符合项目事实并说明必要性。
- 新函数/类型可写简洁 Doxygen；普通改动不添加长篇修改说明。注释优先中文，只描述长期语义、约束和单位。

## 输出

- 当前任务状态和变更摘要。
- 局部检查结果或无法执行原因。
- 下一任务、活动阻塞或进入独立审查的建议。

关联任务完成后统一进入独立 `code-review`，不要求每个小任务单独终审。
