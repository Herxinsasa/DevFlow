DevFlow 发布说明

未发布版本 - 2026-07-15

一、新增内容

- 影响面分析增加技术中立的端到端链路闭合，覆盖客户端或前端、通信边界、服务端或接收端、持久化或缓存以及返回展示。
- 增加同名对象消歧规则，要求记录完整路径、真实符号、职责和可修改性。
- 编码与审查记录增加自定义 Agent 名称和执行标识。
- 开发计划增加独立的 VERIFY 验证清单。
- 提交前审查 Hook 增加独立 code-reviewer 执行标识校验。

二、调整内容

- docs/05-UI 仅保存 UI 稿解析、界面契约和 UI 验收依据；前端或客户端技术设计统一写入需求设计。
- 前端或客户端与后端或服务端技术设计保持在同一份需求设计中，跨层契约必须闭合。
- 需求设计中的正式 TASK 改为无状态的实现分解建议；正式任务仅由 dev-planner 生成。
- 编码顺序调整为依赖优先和契约优先，不机械要求一次性先修改全部头文件。
- 文档减少重复影响面、查询流水和无关章节。

三、问题修复

- 阻止需求、影响面、UI 或详细设计仍有编码相关未决项时自动进入后续阶段。
- 阻止 implementer 或 code-reviewer 不可用时由主 Agent 代替执行。
- 防止新增字段仅修改 UI 和服务端，遗漏中间请求适配、转换、序列化或反序列化层。
- 区分自动化测试代码任务与编译、联调、端到端和回归测试执行。

四、升级说明

1. 使用新版 .claude 覆盖目标项目中的旧版流程文件。
2. 删除遗留的 Stop hook 配置和 .claude/hooks/stop-gate.ps1。
3. 重启 Claude Code，使 .claude/agents/implementer.md 和 .claude/agents/code-reviewer.md 在新会话中生效。
4. 确认当前仓库已执行 git config core.hooksPath .claude/hooks。
5. 旧需求文档无需批量迁移；继续开发时按新门禁补齐未决项、影响链路和 Agent 执行记录。

本次不引入进化系统、自动升级器或 test-designer，保持现有主流程和目录架构不变。
