DevFlow 1.1 修订记录

修订日期：2026-08-13

新增

- 增加需求开发、Bug 修复、咨询只读三类入口。
- 增加按需触发的 design-maker UI 原型流程。
- 增加 progress.json 1.1 状态模型、待办输入和受控历史。
- 旧版 milestones 数组升级时转换为阶段状态对象并保留恢复信息。
- 增加构建指纹凭据，避免测试与提交阶段重复构建。
- 构建凭据校验暂存代码与工作区一致性，防止构建内容和提交内容错位。
- 增加 Python 安装升级工具、版本清单、哈希冲突检测和状态迁移。
- check 命令增加 core.hooksPath 配置检查，不自动修改目标项目。
- 默认升级备份保存到目标项目的 Git 目录，不产生待提交文件。

修改

- T0/T1 使用一次开发前确认；T2/T3 保留需求、影响面和详设三次确认。
- T1 原则上不生成详细设计；需要正式详设时升级为 T2。
- T0/T1 影响结论合并进需求规格；T2/T3 独立归档完整影响面。
- T2/T3 缺少代码图谱时须经用户确认降级，并标记为受限闭合。
- 需求规格、影响面、详设和开发计划模板改为短结论、单一字段语义和当前事实。
- 开发计划只承担任务派发、状态管理和验证，不再保存执行流水。
- 任务按可交付行为拆分，不再按文件、函数和重复接入点拆分。
- T0 和简单 T1 可由主 Agent 编码；连续相关任务可复用 implementer 上下文。
- 审查和测试按 T0-T3 裁剪归档深度，保留所有代码独立审查与必要验证。
- AI 无法测试时生成用户验收清单，不把未执行验证标记为通过。
- Bug 修复复用最小失败上下文，自动修复最多两轮，环境问题首次识别即通知。
- 用户自测期间的 Bug 修复只做针对性检查，审查和构建按用户要求执行，提交前对最终代码强制补齐。
- Qt Widgets 静态控件优先使用 .ui；注释只描述长期语义，禁止长篇改动说明。
- 模块和架构回写必须先参考项目设计文档，AI 推测不得直接写入长期文档。
- 文件名使用稳定迭代 ID，需求主题移入文档标题。
- `pre-commit-check.ps1` 改为按代码指纹复用有效构建结果，不再每次提交无条件重复构建。
- 修复 Windows 中文路径下构建凭据读取 Git 输出可能解码失败的问题。
- README 补充手动拷贝升级时可替换、需合并、必须保留和应删除的文件范围。
- 补回各 Skill 的内部工作流程、自检清单和关键输入边界，避免文档瘦身误伤执行质量。
- 补回提交说明、审查、测试和 Bug 修复的定制输出模板，补全编码输入清单与 Skill 完成前自检门禁。
- design-maker 收窄为 UI 原型交付，保留 Figma、Pencil、HTML/CSS 和 Canvas/PNG/SVG 输出路径。
- 明确 spec-analyzer 使用需求规格模板，并统一 DevFlow 受管文档路径规范。
- 补回 CLAUDE 与关键 Skill 中会影响调用稳定性的调度规则、进入门禁、输入约束和路由规则。

删除

- 删除独立 ui-designer 阶段及其参考文件，原型能力并入按需 design-maker。
- 删除开发计划中的 Agent 名称、Agent ID 和状态变化日志。
- 删除详设中的实现分解建议和重复编码上下文。

升级说明

- 推荐执行 `python scripts/devflow.py check --target <项目>`，再执行 dry-run 和正式 update。
- 默认升级会备份 `.claude`，保留项目定制、运行状态和项目 docs。
- 冲突文件不会被默认覆盖；确认可舍弃定制后才使用 `--force`。
- 升级后确认 `core.hooksPath=.claude/hooks` 并重启 Claude Code。
